# 用量、额度与耗时账本

从 v0.2.8 起提供独立的个人账号统计能力。它独立于 SDK 原生历史、本机恢复日志和有轮转上限的诊断日志；不扫描聊天正文、不回填历史，也不估算订阅总额度或美元与百分比的固定换算。

## 存储与可靠性

WebSocket 父服务在 `<BRIDGE_REMOTE_ROOT>/observability/observability.sqlite` 维护 schema v1 账本，所有设备 worker 通过私有 Node IPC 使用同一写入端。Node 内建 SQLite 在独立 worker thread 运行，短事务、短锁超时、有界队列和操作超时保护会话 I/O。目录权限 700、数据库 600；备份仍应按私有数据管理。

运行、响应、耗时和额度观察分表；同一身份幂等更新。身份包含设备、DSH 会话、SDK 会话、run，响应观察另含 response ID。缺失数据保持未知，取消或失败不伪造成功用量。响应明细供审计，汇总只加整轮主代理权威用量，不重复加响应、子代理或会话累计 modelUsage。

SDK 的费用是会话累计等价 API 费用，不是订阅实付。账本保留累计观察值，只有相邻且可排序的已知基线才推导区间差值；首次无基线、计数回退和同时间歧义保留未知。按日汇总使用 UTC；这不代表用户所在地，也不会向模型注入时区。

统计写入失败、队列溢出或不可写会留下固定错误码及缺口诊断，设置页可见，不能中断对话或重放工具。尚未实现后台补写重试；可查询数据可能不完整。当前版本不自动清理账本，维护者应关注磁盘与备份。直接 SSH stdio worker 没有父服务 IPC 时不声明账本能力，基础会话继续可用。

## 额度查询

实际运行中的远程任务才计为活跃，单纯连接、打开窗口、查看历史和查询账本均不算。账号父服务只维护一个采样器：首个任务开始且冷却已结束时允许一次读取，之后活跃期间每 2 分钟最多一次；多设备、多会话共用结果。失败指数退避，最长 1 小时，并遵守更长的 retry-after；并发请求合并为一次。

最后一个任务正常结束时停止周期采样，并在冷却和退避允许后补采样一次，标记为 run-end。等待期间有新任务时恢复活跃采样。worker 断开本身不触发补采样。空闲时手动入口只返回缓存。超时后实际未结束的读取继续占用 singleflight，调用者取消不能释放账号级 gate。

缓存命中不新建额度观察、不改变 observedAt。新鲜度最多 2 分钟；超过 30 分钟或窗口重置后，旧百分比不能作为当前余额。

v0.2.9 保留单独的最后历史快照：长期空闲仍可显示“上次剩余”、原观察日期及时间；已过重置点的窗口明确标示当前额度待刷新，不推算重置后的余额。历史缓存与当前有效窗口分开，认证／版本门禁和连接身份变化会清除旧身份读数。空闲打开面板或手动读取仍不触发上游查询。完整修复需要更新两端。

父服务重启后，只从本机私有账本恢复最后一次成功快照，原 observedAt 和窗口不变，始终标为非新鲜，也不改变冷却时间或主动读取额度；下一次真实任务照常采样后替换。快照不带账号身份，因此显式登录复核、未登录或不支持的登录方式视为账号边界：清除父服务内存中的读数，作废边界前已发出的读取，并在账本写入一条边界记录；边界之后（含同一时刻）或认证类失败之后的旧快照，重启时不再恢复。账本不可用或读取失败时按无快照启动，不阻断服务。

最后快照来自父服务当前内存中的成功采样。父服务重启后采样缓存重新建立；本次修复不新增持久缓存恢复，历史读数仍可通过账本查询。

此限频以一个账号只运行一个本项目父服务为前提，不能跨多个独立部署实例协调账号采样。当前不部署外部账号轮询任务，也不能承诺特定调用频率不会触发上游限制；遇到限制保持退避，不绕过。

## 耗时口径

有效输出包括非空思考、正文或工具参数内容；开始帧、心跳、工具名和签名不算首 Token。

| 观察 | 粒度和来源 | 精度与限制 |
| --- | --- | --- |
| 本机首有效输出 | run，`local-rpc-first-output`，RPC query 写入前至原始通知解码后 | 同机单调时钟边界精确；包含传输和解码等待，不含发送前历史核对，也不是逐响应上游 TTFT |
| 上游首有效输出 | response，`sdk-first-output-estimate` | SDK 首帧耗时加远端观察间隔的估算；缺证据则未知 |
| 远端运行总耗时 | run，`remote-worker-run` | 远端 worker 入口至收尾的同机间隔精确；含工具与 SDK 等待，不是纯模型耗时 |
| 远端接收速度 | response，`remote-sdk-stream-receive` | 完整原始接收窗口配同一响应的最终输出用量；仅接收观察估算，缺流、取消或缺最终用量则未知 |

每项记录 side、level、metric、source、clock、quality（precise／estimate／unknown）；不得相减两台机器的墙钟。查询与汇总按来源和精度分组，不把本机与上游 TTFT 混为一个数。

固定 SDK／CLI 版本没有公开的逐请求发送及首有效 Token 成对时间接口。CLI 的 first_content_frame_ms 对任意内容帧计时，空块、工具头也可触发，不能冒充首有效输出。当前没有改官方 SDK／CLI、启用额外请求日志或以帧计时宣称精确上游 TTFT。

界面继续使用既有逐响应 TTFT／TPS 统计；新增本机精确 run 观察保存在账本中，尚未把两类粒度混入原生平均值。底栏只保留数值，完整性、样本与来源进入悬浮详情，实际错误仍显示。

## 只读查询

使用已有 Node.js，连接文件为用户自己保存的私有 JSON（`url`、`token`）。不能把文件内容、地址或口令提交到仓库。

```powershell
node scripts/query-observability.mjs --connection <私有连接文件> --kind runs --from <ISO时间> --to <ISO时间>
node scripts/query-observability.mjs --connection <私有连接文件> --kind timing --limit 100
node scripts/query-observability.mjs --connection <私有连接文件> --summary day
```

`--kind` 支持 runs、responses、timing、quota；时间范围左闭右开，默认近 30 天、最多 366 天；单次最多 500 条并返回 hasMore。可按 device、model 筛选运行类记录，账号额度不按设备或模型归属。汇总支持 none、day、model、device，未知用量和未知费用差值单独计数；这里只汇总已有数值，不发模型请求或触发额度采样。

协议增加可选 observability 能力。旧服务仍可连接，但不支持此账本；新服务接受旧客户端，旧客户端没有本机精确计时上传。运行中插话需双方支持 userInputViaStream；新版客户端连接不支持的旧服务时保留未消费插话并明确拒绝，不能降成 Hook 文字。

## 部署、升级和回退

新安装按[部署说明](remote-service.md)提前创建 observability 私有目录，并允许 systemd 仅写该目录。已有只读 unit 需要在用户授权升级时加相同 ReadWritePaths；不能为了统计开放整个 home。目录不可写时统计降级并告警，会话照常运行。不要在实际任务运行时替换源码或重启。

回退源码前保留数据库与私有会话；旧版本忽略新目录，不能删除原 SDK 绑定、迁移聊天正文或将 DSH 历史伪造成 SDK 恢复。未来不支持的 schema 版本只禁用账本并报告，不能覆盖数据库。
