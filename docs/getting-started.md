# 首次使用与自部署指南

DSH Claude Bridge 是支持**个人账号、多设备自用**的实验性桥接：各台本机 DSH 管界面、文件、命令、审批和展示历史；你自己的 Linux VPS 运行官方 Claude Agent SDK，负责真实 Claude 会话和压缩。本项目不提供公共服务器、账号或登录材料。

**本项目由人工驱动的 vibe coding 完成。**

## 先准备两端

| 本机 | 自己的服务器 |
| --- | --- |
| DSH Desktop，实测基线 `0.2.1-rc.5` | Linux VPS、独立非 root 服务用户及独立部署目录 |
| `v0.1.4` 插件 | Node.js `>=24.9`、npm、锁定 SDK `0.3.314` |
| 无需安装 Claude Code 或 SDK | 官方 CLI `2.1.314` 和本人具备使用权限的 `claude.ai` 登录 |

上表是本项目的要求及实测范围，不是最新版声明。DSH 其他版本会按实际接口能力检查，仍需确认使用效果；服务器 SDK/CLI 不应静默升级。本人账号的其他设备可使用同一自部署服务，但各设备独立生成身份和历史，不复制整个 DSH 数据目录。

尚未部署时，先按 [远程服务部署](remote-service.md) 完成独立目录、版本准备、本人官方登录、独立桥接口令及 systemd，然后选择 WSS 或 SSH 转发。安装源码和启动服务不会替你完成 Claude 登录。服务监听或 systemd 显示 active 也不等于模型链路已经可用。

部署完成后，你需要两项独立配置：

- 服务器地址：自己的可信 `wss://` 域名，例如占位地址 `wss://bridge.example.invalid/`；或 SSH 转发后的 `ws://127.0.0.1:18944/`。
- 桥接口令：自己在服务器生成的 `private/service-token` 内容，属于桥接访问凭据，不是 Claude 登录令牌。

`.invalid` 是示例占位域名，实际使用须换成自己的域名。不要在 URL 中附加口令、用户名、密码、查询参数或片段，也不把口令发给项目维护者。

## 安装插件并连接

1. 安装并打开 DSH。若本机已有日常数据，用独立配置和数据目录试用，不改动其他插件和既有会话。
2. 在“插件 → 添加插件”填入固定标签：

   ```text
   https://github.com/yyjsjsjx-png/dsh-claude-bridge#v0.1.4
   ```

   如果 GitHub 安装路径不可用，从 [v0.1.4 Release](https://github.com/yyjsjsjx-png/dsh-claude-bridge/releases/tag/v0.1.4) 下载插件 ZIP，解压后添加其中包含 `package.json` 的目录。启用 bundle，并按 DSH 提示重载。Release 已包含运行文件，使用者无需编译。
3. 打开“设置 → 远程 Claude”，填写自己的服务器地址和独立桥接口令，保存后点击“测试连接并刷新模型”。这一步核对连接、官方登录及目录，不发送聊天提示词。
4. 在会话首页点“新建远程 Claude”，选择账号目录实际返回的明确模型和受支持强度，再创建会话。不要依赖未知账号默认模型；普通原生“新会话”也不等价于此专用入口。
5. 先用一条简短消息确认实际回复和本机工具权限。开始真实对话及工具任务会消耗你自己的 Claude 账号额度；模型目录成功不能代替对话验收。

## 在自己的多台设备使用

每台设备独立安装 DSH 和插件，填写**相同的服务器 URL 和桥接口令**即可；各设备首次运行会生成独立 device ID，不需要重新给服务器 Claude 登录。请保存好自己的连接凭据，连接方式没有绑定某一台设备。

不要复制整个 `DSH_HOME` 来配置第二台设备，否则连同 device ID 一起复制，可能发生身份冲突。各设备有独立历史，聊天记录不会自动跨设备共享。不同 SDK session 可以并行，同一 session 的运行和维护串行；所有设备仍共享同一账号额度和服务器资源，可能受到上游限流。

服务默认最多保留 16 个连接槽位，包含短断保留项；它不是 16 路推理并发的承诺，也不代表订阅允许的模型并发数。同一服务地址和口令只应提供给本人受信任的设备。device ID 是会话命名空间，不是多租户权限边界；本项目没有账号级公平排队或并发容量保证。

## Windows 保留数据更新

1. 下载 [v0.1.4 插件 ZIP](https://github.com/yyjsjsjx-png/dsh-claude-bridge/releases/download/v0.1.4/dsh-claude-bridge-0.1.4.zip)，解压到 DSH 数据目录以外。
2. 等当前任务结束，完全退出 DSH，包括托盘程序。
3. 双击包根目录的 **`更新插件.cmd`**。结果窗口会保留；仅在 Windows 确实要求提升权限时请求 UAC，提权前确定的目标目录不变。拒绝 UAC 会明确提示未执行，安装失败不会自动重复执行。
4. 看到成功版本后，按回车关闭窗口并重启 DSH，核对插件版本及原会话。

请保留解压目录，更新后的依赖会引用它；不要通过还原纯净快照升级，否则旧历史及设备身份也会一起丢失。自定义 `DshExecutable`、`DshHome`、`Profile`、`PackageDirectory`，以及元数据备份和失败处理见 [更新说明](updating.md)。

## 日常使用与恢复边界

- **审批与停止**：命令在本机 DSH 工具中执行，沿用 DSH 权限和审批。单项或整轮停止不代表已经发生的文件、进程或外部副作用被撤销。
- **短暂断网**：原 RPC 与 worker 在有界窗口内接续，补帧并去重。默认客户端重连窗口 60 秒、服务保留 worker 90 秒；不能把它当作任何断网情况下均自动续跑的保证。
- **进程崩溃或重启**：可以补齐 SDK 原生记录并继续下一条对话；消失的调用栈不会恢复，结果未知的工具不自动重跑。先用只读检查核实实际状态。
- **恢复提示与上下文**：恢复后可以直接发下一条消息。正常新轮次会更新当前上下文；历史未知工具结果可继续保留核实记录。上下文是 SDK 近似快照，缺少快照时显示未知，不用 DSH 历史伪造数值。
- **中途补充消息**：执行中追加的文本在工具批次边界通过 SDK hook 送达；模型对附加上下文的响应存在差异，不保证即时回应或逐字复述。要中止执行请点停止。模型自然结束一轮也不会由桥接自动发起下一轮。
- **上下文与额度**：真实上下文和 `/compact` 由 SDK 管理。底栏显示有效的 5h 额度，其余明细仅在账号接口实际返回时出现；没有某种明细不等于计费失败。
- **暂不支持**：会话分叉、`subagent_fork`、计划模式、DSH 本机压缩和步骤/工具附加图像上下文。普通新建子任务与会话分叉是不同能力。

`/bridge-recovery` 可查看未知状态；实际核实后，`/bridge-recovery confirm` 可允许后续运行，但不会把旧未知结果改成成功。“清除已保存连接”只清除本机地址和桥接口令，保留会话及服务器 Claude 登录，也不撤销其他设备的同一口令。

## 日志与可选人工检查

遇到异常时记录 DSH/插件版本、本地时间和时区、所做操作及表面现象。先查看“设置 → 远程 Claude → 诊断”中的本地诊断目录，再按 [性能诊断](performance.md) 使用现有 Node 或 DSH 自带运行时生成脱敏报告；不要为采集额外安装 SDK、Node 或浏览器，也不必重复发送模型请求。

可发给维护者的是收集器生成的 `performance-report.md`、`performance-report.json`、`diagnostics.sanitized.jsonl`、`collection-manifest.json`，以及不含私人信息的简短操作说明。不要附整个 DSH_HOME、原始 Host stdout/stderr、`state.json`、`connection.json`、认证目录、服务器会话、历史备份或桥接口令。耗时报告用于区分本地准备、云端等待及工具过程，不能单凭它断言网络或模型是根因。

[v0.1.4 Release](https://github.com/yyjsjsjx-png/dsh-claude-bridge/releases/tag/v0.1.4) 的网络波动测试工具和人工验收包作为额外附件提供，不属于日常连接必需步骤，也不包含在插件主 ZIP 中。按附件自己的说明运行：断网工具只在独立测试虚拟机使用，会影响所选网卡的全部连接；预备完成后才点击“立即断网”，等待时长从确认禁用后开始，驱动和重新联网还会增加实际中断时间。不要在有重要连接的宿主机随手测试。

## 常见问题

| 现象 | 处理 |
| --- | --- |
| 插件无法加载 / `DSH_API_INCOMPATIBLE` | 查看明确缺失的接口；上表以外的 DSH 发行版没有逐版实测，不靠修改版本号绕过能力检查 |
| 地址被拒绝 | 公网使用有效可信 WSS；明文 WS 只允许 `127.0.0.1` 或 `localhost`，且须已建立 SSH 转发 |
| TLS 正常但认证失败 | 核对桥接口令；若提示 `AUTH_REQUIRED` / `AUTH_EXPIRED`，由本人在服务器原配置目录重新登录 Claude |
| 目录无模型或强度不可用 | 刷新账号目录并选择实际返回值；没有特定型号时不猜测或强制使用默认型号 |
| 更新报旧 GitHub 包的 `ERR_PNPM_NO_OFFLINE_TARBALL` | 换用 v0.1.4 完整更新包并双击更新，不下载旧压缩包来填缓存，不关闭离线模式 |
| 更新失败 | 保留窗口显示的备份与实际 `pnpm.log` 路径；安装日志和外层 `.err` 是两层不同文件 |
| 工具显示“待核实” | 先核对文件、进程或外部状态；不要把“没有回执”当成“没有执行” |
| 运行中发消息却未立刻照做 | hook 附加上下文的响应由模型决定；需要结束当前操作时使用停止按钮 |

更详细的部署故障检查见 [远程服务部署](remote-service.md)，功能验证与未覆盖范围见 [兼容与验收清单](compatibility-inventory.md)。
