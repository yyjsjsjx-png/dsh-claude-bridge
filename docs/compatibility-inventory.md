# 兼容与验收清单

基于 DSH `0.2.1-rc.5`、官方提交 `b830ec950faba0a46dda564be3e2d854afed94f1`，SDK `0.3.314`、CLI `2.1.314`。检查日期：2026-11-01。

上述 DSH 版本为实测基线，运行时不锁版本号或源码摘要。加载前检查必需导出、核心方法、源模式 RPC 参数和内存中的原生会话回放；缺失关键接口时返回 `DSH_API_INCOMPATIBLE`，明确提示插件无法加载。兼容的未来版本模拟已通过；其他真实 DSH 发行版尚未逐版验收。

基线 DSH 出厂 Web preset 有 22 个顶层配置条目，一个条目可能注册多个工具。桥接读取当前安装版的声明并检查关键结构，允许新增普通工具；普通 DSH 会话继续使用原引擎，不假定复制了用户自行修改的活动 preset。

## 七类故障链路

使用现有 Windows OpenSSH、VPS WebSocket 服务和 worker、真实 BridgeBackend/RPC/台账、已安装 DSH 的 Session/投影及 fsync 日志。工具会启动真实本机进程并写合成副作用文件；仅 SDK 替换为确定性实现，不加载真实 SDK/CLI，不发模型提示词。

| 场景 | 已验证行为 |
| --- | --- |
| 工具运行中短断 TCP | 接回同一运行，工具仅执行一次 |
| SSH 进程退出 | supervisor 重建转发，原 query 不重发 |
| 断网时整轮停止 | 本机工具进程取消，零副作用、无晚到尾部 |
| 本机桥接客户端 SIGKILL | 重启补齐原生尾部、核实已有结果、续聊成功 |
| 远端 worker SIGKILL | 新 worker 同步历史并续聊，不重执行工具 |
| 服务主进程 SIGKILL | 服务重启后同步记录并续聊 |
| 副作用已发生、回执丢失 | 结果仍未知；下一条带核实建议，再下一条不重复注入 |

此前七项故障验收分别通过，原 query 均只派发一次；该批验收新增真实模型请求 **0**。这覆盖用户认可的全链路故障模拟；真实 CLI 既有图片、停止、压缩等少量样本沿用先前结果。

运行夹具需要已有独立服务器、既有 Node/依赖和管理 SSH，不安装测试工具：

```powershell
$env:BRIDGE_E2E_SSH_TARGET='your-test-alias'
$env:BRIDGE_E2E_REMOTE_DEPLOYMENT='/home/bridge/dsh-claude-bridge'
$env:BRIDGE_E2E_REMOTE_USER='bridge'
$env:DSH_CLAUDE_BRIDGE_RESOURCES='DSH安装目录\resources'
node scripts/recovery-e2e.mjs
```

可用 `BRIDGE_E2E_SCENARIOS` 选择逗号分隔的 `short-drop,ssh-restart,offline-stop,host-crash,worker-crash,server-crash,unknown-result`。夹具只操作自己创建的独立 `validation/recovery-*` 单元、目录、端口和进程；报告保存在被忽略的 `.local` 中。它需要 Linux systemd 管理权限和 Windows 本机工具环境。

## 常规检查

`npm test` 不需安装 SDK。使用已有 DSH Electron 的 Node 模式运行 ASAR 专用用例，普通 Node 下这些检查会明确跳过；跳过不计为通过。服务初始化和模型目录读取仅验证连接、登录和协议，不做推理。

此前完整验收有 158 项普通 Node 用例通过，16 项 Electron 专用用例亦已通过，共 174 项不同用例，无失败。实际隔离页面已完成自动历史同步；原生消息分支请求返回明确的 `session/fork-unavailable`，未创建分叉。

## v0.1.2 停轮续聊与性能诊断

修复同一 Agent 跨轮流式 revision 重置、完整回复后的空结算风险，以及历史只补尾部却被 DSH 当作整步替换的问题。相同响应的多个工具片段保存累计快照；恢复按原生响应分配步骤并保留已有位置。只过滤来源和内容均精确匹配的 CLI 停轮占位，不过滤普通同文回复或其他 synthetic 错误。

83 项直接相关普通用例、13 项 DSH 原生用例通过，无跳过或失败；性能报告最终变动另外定向复验。使用先前 3 次自建小额 Haiku 请求保存的真实 SDK 事件，回放完整 Backend、原生 Session 持久化与原生客户端 fold，29 帧跨轮连续，停轮后两次续聊及旧占位遮挡后的历史修复通过；回放新增模型请求为 0。SDK 独立采样不等于虚拟机 UI 实测，用户升级后的回访仍需人工确认。

前台空闲每 30 秒核对、离线/隐藏/执行时暂停、请求合并及清理均有定向回归。性能收集器检查两端对应、首思考与首正文区分、累计 SDK 字段边界、脱敏导出及无效行报告；未为此安装依赖或浏览器。分段记录从升级后开始，不把旧整轮日志推断成首 token 数据。

设置页新增“清除已保存连接”：删除本机地址和桥接口令，保留 BridgeState 设备及会话，拒绝活动运行、准备阶段或历史同步中的清除。连接切换会中止旧初始化，迟到的目录、额度、认证及前端响应不再恢复旧缓存。相关普通检查 89 项通过；新增 owner-only RPC 与既有模型服务 3 项原生检查通过。先前已通过的其余检查按未变动范围复用。

本版本不保证任意后台进程树、复杂父子任务、所有附件格式、跨设备历史共享或多人公网 WSS 隔离。系统提示快照改变会明确拒绝静默续用，不能用本机展示历史伪造 SDK 会话。

## v0.1.3 历史重载、热启用与原地升级

旧历史补齐向已结束的 turn/step 写入原生 assistant/message，内存重放可能正常，磁盘读取却会拒绝。现在补齐文字和已核实工具结果使用可忽略的插件记录，展示仍沿用原生 renderer 并固定原步骤位置。实时片段只为新工具写原生广告，累计快照另存展示记录，避免重复打开已完成工具的生命周期。

此处更正此前验证口径：Session.create 的内存回放不能代替完整的磁盘格式校验。新增实际 sessionFormatCatalog 严格校验，覆盖闭合历史修复、已核实工具结果和同响应多个工具；原生分组验收包括思考、调用顺序、最终答复及重载。Windows 离线迁移用例实际验证压缩帧、原件备份、原子写回和重复运行不改写；无法证明安全的旧日志拒绝迁移。

热启用和卸载使用真实配置图验证原生控制器、预设注册器及核心客户端模块身份不变，RPC 描述未丢失，策略能清理。真实服务创建空白远程会话和读回选择成功；内置浏览器亦确认创建后再次打开窗口预选上次模型和强度。原地更新使用现有 DSH 的包管理器，实际完成旧版到 0.1.3 的安装切换及路径核对；Windows PowerShell 默认包目录和集成历史检查后的重复更新也已实际运行。三个既有私有状态文件的大小及修改时间未变，未读取认证内容。GitHub URL 的自动安装验收此前被工具自动审批阻止，不能算已通过；本地包路径已经实测。

“新建远程 Claude”记住上次模型和有效强度，远程选择不写普通新会话的全局默认。旧版已污染的远程默认在创建前明确拒绝，不生成不匹配会话。相关后端、选择守卫、原生 RPC 和 UI 检查通过；不发新模型请求来验证目录、创建空白会话或升级。

此前七类故障模拟按未变更的传输和服务范围复用；虚拟机上的升级后视觉回访由使用者按测试清单确认，未冒充为本机验收结果。客户端修复不要求升级服务器 SDK/CLI。

## v0.1.4 恢复状态、升级入口与用户回访

修复历史恢复标记长期覆盖当前状态的问题：后续正常轮次更新当前上下文，旧未知工具结果仍保留核实记录。使用者在 Windows 测试虚拟机确认修正版升级、不断网对照及 2 秒短断符合预期；模型自然结束一轮和传输故障分开判断，不为延长回复自动重发工具或新建推理请求。

从 GitHub 安装的旧依赖以带包名的本地 `link:` 替换，保持离线安装；不再为了原地更新回取旧 GitHub 压缩包。双击 `更新插件.cmd` 复用同一更新脚本，仅结构化识别 Windows 740 时请求 UAC，提权前固定四个目标参数。成功、失败和 UAC 拒绝均保留结果窗口，安装失败不自动重试。Windows PowerShell 5.1 的 wrapper 4 项和入口 7 项纯模拟检查通过，真实更新与模型行为的证据范围分别记录，不把模拟 UAC 当成真实 UAC 验收。

网络波动工具是独立的人工验收附件，预备 worker 后通过命名事件触发，不在插件主包中安装网络组件。预备取消、GUI 退出、独立恢复及计时口径有纯模拟检查；这些模拟不代表宿主机实际断网或任意网卡驱动的时延保证。

本轮开发与定向复核由主代理及经使用者明确授权的开发子代理完成。此过程安排与插件在 DSH 中提供的普通子任务能力是两件独立的事。当前仍面向个人账号所有者自用，多租户权限隔离和复杂并发容量不在验收范围。
