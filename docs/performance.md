# 性能诊断与脱敏报告

v0.1.2 默认记录诊断元数据，不记录提示词、回复正文、思考正文、工具参数、原始错误或认证材料。日志属于设备私有数据，不随插件上传。

| 日志 | 位置 | 范围 |
| --- | --- | --- |
| 本地 | 设置 → 远程会话 → 兼容性与诊断中显示的目录，通常为 `<DSH_HOME>/claude-bridge/diagnostics` | 本地准备、历史核对、发送、首模型事件、首 token、首段正文、整轮及收到的云端诊断 |
| 云端 | `<ROOT>/sessions/_diagnostics/<device-id>` | CLI/hooks 和工具集初始化、首模型事件、首 token、首段正文、SDK 原始耗时与结果 |

两端均保留 `bridge.jsonl` 与 `bridge.previous.jsonl`，每份上限 2 MiB。云端日志写入与诊断转发分别执行，短断不会使云端日志丢失。新增记录从升级并重启后开始，旧日志无法补出从未记录过的首 token 时间。

## 运行中的用量与上下文

v0.2.6 起，远程 Token 用量在每个有效响应报告后更新，整轮结果以 SDK 主代理四桶报告核对；输入、缓存读取、缓存写入和输出互斥计数。累计缓存流量可能多次包含同一前缀，不能当作当前上下文大小、费用或订阅扣额。旧历史缺少可信明细时显示不完整，不自动补造。

上下文使用 SDK 的近似 summary 快照，按响应／工具批次边界后台限频采样，并显示采样时间；运行中和离线看到的都不是逐 token 实时分词结果。采样失败保留旧值并提示，自动压缩状态及 SDK 报告的数值边界单独展示。上下文压缩后可以下降，不要求它与累计 Token 总量一致。

模型目录的 Host 与 VPS 成功缓存均为 6 小时，按需读取、没有新的后台轮询。正常 SDK Query 的初始化已有合法 models 时更新 VPS 缓存，无须为续聊另起一次目录初始化；冷启动、到期或显式刷新时仍可读取。认证检查的周期与目录缓存分开；已知认证失效、显式重新验证登录、清除／更换连接使旧缓存失效。实现不读取账号 ID，不能承诺自动识别静默的已登录账号切换，重新登录后应显式刷新；实际 SDK 仍校验本次账号和模型权限。

## 响应级 TTFT 与 TPS

v0.2.7 起，远程会话的底栏按响应更新计时，并注明各指标的有效样本数。轮数、步数及模型／工具耗时继续使用 DSH 原生统计；TTFT 和 TPS 仅汇总有对应证据的响应，不能据此代表所有历史响应。

DSH 原生底栏、图标及四项统计浮层保持不变。“首 Token 平均（TTFT）”自 v0.2.11 按每个模型请求／响应周期的 Host 客户端计时汇总，包含工具续推理，不再只以用户点击发送为分母。首步从 Host 准备本次请求的入口起计，包含绑定、目录能力核对和检查点；工具续步从本批最后一个工具结果交给 RPC 输出流起计，经成功的 PostToolBatch/step.prepare 回执确认归属。终点是同一实际 SDK responseId 的首个有效内容到达本机，全部使用本机单调钟；包含上传、VPS 处理、SDK 等待和下行，以及仍在计时范围内的续步准备。它是 Host 应用边界，不冒称 SDK 上游精确发包或浏览器像素绘制时间。

SDK 首有效输出估算继续独立保存在响应统计和诊断中，不混入客户端均值。在服务器收到首个非空思考、文字、工具参数或合法工具调用开始帧后估算：SDK 报告的当前请求尝试至响应开始帧的耗时，加上服务器从开始消息到该输出的接收间隔；此前的重试与退避不计入此估算。合法 tool_use 开始帧具有非空工具名和调用 ID 即有效，参数为空也无需等增量；消息开始帧、心跳、签名和空文本／思考增量不算有效输出。SDK 缓冲与服务器调度仍会影响结果，因此它是首有效 Token 的观察估算，不是上游精确生成时间；不会用整轮 query 起点或本地 RPC 等待补造。

TPS 将同一完整响应的输出 Token 与本机收到原始 SDK 开始消息至最后有效内容帧的时长配对，再按总 Token／总时长汇总。它是接收观察速度，包含思考阶段和缓冲影响，不代表上游生成测速。缺少完整流、有效输出用量或正时间跨度时，该响应没有有效 TPS 样本；数值高低本身不是剔除依据。

每个实际主模型响应单独记录 TTFT、从同一起点至原始 message_stop 的总时长和未知原因；多个工具合成一个批次不按工具数扩大分母。SDK 子流不抢主响应；子代理自己的运行另记。合法 tool_use 开始帧具有工具名和调用 ID 即算模型输出，空参数工具不必等 JSON 增量；文字、思考仍要求非空，签名、心跳和占位消息不算。新数值记录随 DSH 历史持久保存，重开窗口仍可汇总；旧历史缺少单调起点不补造，不以 SDK 值回填。

SDK/TPS 缺证据时显示计时样本不足或部分计时，不回退旧速度。旧会话保持可读，但不会从消息长度、完整回复或旧原生计时倒推新样本。首有效 Token 的 TTFT 估算需要支持该数据的新服务器；连接旧服务器时保持未知，不要求客户端与服务器版本相等。

## 每模型请求明细

SDK 用量按 runId + responseId 记录未缓存输入、缓存读取、缓存创建及输出，工具结果会进入下一次请求的输入；终态整轮总计用于核对，不能再与响应暂计相加。三种输入桶完整时可列出本次报告输入量，不能把跨请求累计 Token 当作当前上下文。上下文压缩后可以下降，SDK 未单列的思考 Token、实际 effort 和单请求实付费用保持未知。

Host 的 modelRequestStats 只读接口按已加载远程会话的数值投影分页（默认 100、最多 200），不激活 Agent、不查模型或读取正文。导出 CSV 同样只含元数据。v0.2.10 的浏览器用户提交到首输出仍作为独立 perf.client 诊断，不能代替模型请求分母。

## 收集与分析

用已有 Node.js 或 DSH 自带 Electron 的 Node 模式运行，不需要安装依赖：

```sh
node scripts/collect-performance.mjs --logs /path/to/diagnostics --out /path/to/new-report
```

服务器使用已有 runtime，例如：

```sh
/srv/dsh-claude-bridge/runtime/bin/node /srv/dsh-claude-bridge/scripts/collect-performance.mjs \
  --logs /srv/dsh-claude-bridge/sessions/_diagnostics \
  --out /srv/dsh-claude-bridge/sessions/performance-report-unique
```

`--out` 必须是尚不存在的目录。脚本只读取两份桥接诊断及已导出的 `diagnostics.sanitized.jsonl`，输出：

- `performance-report.md`：P50、P95、最大耗时和每轮表格。
- `performance-report.json`：相同指标及每轮原始数值点，缺失值保留为空缺。
- `model-requests.csv`：按匿名 runId + responseId 一行，包含 Host TTFT／请求总时长、SDK 估算／接收 TPS、四桶 Token、请求档位与实际返回型号；未知为空，不从累计值分摊。
- `diagnostics.sanitized.jsonl`：重新筛选的白名单数据，轮次 ID 稳定匿名，移除会话、设备、路径和任意文本。
- `collection-manifest.json`：输出清单和 SHA-256，不包含源日志路径。

合并本地与云端的收集目录时可重复传入 `--logs`。相同匿名轮次会对应合并，云端诊断在本地已有一份时会去重。不要直接打包整个 DSH 数据目录、Host stdout/stderr 或服务器会话目录。

## 如何判断等待发生在哪里

| 指标 | 含义 |
| --- | --- |
| 本地准备至发送 | 连接、发送前历史核对、工具和提示词准备、持久保存 |
| 云端工具集初始化 | 服务器接到 query 至 CLI/hooks 与工具集验证完成 |
| 云端首 token | 服务器接到 query 至首次非空思考、文字、工具参数或合法工具调用开始帧（带名称和调用 ID） |
| 云端首 token 至首段正文 | 可能在生成思考或工具调用；受 effort 和任务内容影响 |
| 两端传输与调度余量 | 本地发送后首 token 等待减去云端首 token 等待；只是估算，包含调度和传输，不能直接叫网络 RTT |
| SDK 原始字段 | `ttft_stream_ms`、`first_content_frame_ms` 等保留 SDK 标签；`duration_api_ms` 可能累计，不能当作本轮上游耗时 |

两端使用各自单调时钟计算耗时，不直接相减两台机器的墙钟时间。报告可以定位等待所在的阶段；没有上游请求边界证据时，不进一步断言是服务排队、网络或模型推理。

“首 token”表示桥接首次收到可用思考、文字、工具参数或合法工具调用开始帧的观测点；工具调用具有非空名称和调用 ID 即有效，空参数不必等待 JSON 增量。SDK 未提供流式增量时，以首个完整消息到达为准；不把它当作未观测到的真实生成起点。

现有分段不是完整链路的独立归因。连接准备包含绑定，工具准备包含能力检查，发送标记位于 RPC 调用前；本地首输出从 Backend／RPC 边界观察，不包含浏览器实际显示。工具总耗时包含原生审批、执行和记录处理；新增工具管线分段仍含原生审批，不称纯执行。SDK approval callback 等待另列，不能代替 DSH 原生审批时间。`completed` 阶段仍早于部分收尾，新增回调 drain、恢复保存、锁释放、诊断 flush 与本机 finalize 独立区间，异常退出也尽量记录。

WebSocket 连接复用既有心跳进行四时间戳探测，不发模型请求、不读取额度。客户端发送/接收分别为 t1/t4，服务端接收/回复分别为 t2/t3，各进程使用固定 timeOrigin 加单调时钟。应用往返为 (t4−t1)，服务端停留为 (t3−t2)，两者相减得到扣除服务端停留后的往返；仍包含操作系统、WebSocket 和链路调度。

时钟偏差区间为 [t3−t4, t2−t1]；中点作为近似偏差，往返余量的一半作为对称路径下单程估计，并列出半区间不确定度。这依赖探测期间偏差稳定及非负传输时间，上下行不对称无法仅凭四个时间戳消除。报告保留最小 RTT 探测的原区间，不能称作上下行单独实测或纯网络时延。旧服务端不支持时明确记录 unsupported，探测超时不是 TCP 丢包率。

RPC 在 Host 聚合编码、同步写入、完整帧解析、通知排队和通知处理的调用数、累计/最大耗时与字节数，流增量不逐条落盘。同步 write 不代表物理发送完成，receive 不含等待完整帧收齐的时间；这些区间可能互相包含，不能简单相加。既有传输调度余量继续保留，与心跳 RTT 一起判断等待大致位于哪一层。

四时间戳原理参照 [RFC 5905](https://datatracker.ietf.org/doc/html/rfc5905)，单程时延的时钟与测量误差边界参照 [RFC 7679](https://www.rfc-editor.org/rfc/rfc7679.html)。本实现是应用层诊断，不部署或改动系统 NTP，也未采集独立 DNS/TCP/TLS 或内核重传指标。

## 采集步骤

可以在复现一次慢首响应等问题后执行，无需重复消耗额度。也可以把下面的步骤交给本机的 AI 助手代为执行：

```text
为 dsh-claude-bridge 收集一份本地性能诊断包，只用于自己分析或附在公开 issue 中。

只使用现有环境，不安装工具或依赖，不发起模型请求，不重启或改动 DSH、插件及连接配置。不要读取或输出桥接口令、认证文件、Cookie、token、授权 URL、聊天正文、工具参数、浏览器存储或原始 Host stdout/stderr。

1. 从 DSH“设置 → 远程会话 → 兼容性与诊断”确认本地桥接诊断目录，并找到已安装插件中的 scripts/collect-performance.mjs。界面不便读取时，只检查当前用户已知的 DSH_HOME，或当前用户 .dsh/claude-bridge/diagnostics；不要全盘扫描。插件须为 v0.1.2 或更新版。旧版没有分段点时如实说明，不编造数据，也不要擅自升级。
2. 使用已有 Node.js 执行收集器，传入 --logs <该诊断目录> 和 --out <新建且唯一的输出目录>。没有独立 Node.js 时，用本机已安装的 DeepSeek Harness.exe 并临时设置 ELECTRON_RUN_AS_NODE=1；结束后恢复该环境变量。禁止安装 Node.js 或另一份 DSH。
3. 检查只生成 performance-report.md、performance-report.json、model-requests.csv、diagnostics.sanitized.jsonl、collection-manifest.json。确认无真实口令、认证材料、聊天正文、个人路径或 IP；不要附加原始日志和 state.json/connection.json。若发现疑似敏感内容，先移除该敏感记录并重新生成报告与摘要，不把它复制进回复。
4. 可另写一份简短的 test-notes.txt，仅含 DSH/插件版本、测试的大致本地时间与时区、网络是否通过代理、停轮后第一次续聊是否消失、慢响应的大约等待秒数。只使用已知信息，未知项注明未知；不包含用户名、服务器地址、会话标题或对话正文。
5. 使用系统自带压缩功能，仅将上述新建输出目录里的文件打成 ZIP 放到桌面，保留目录便于复查。最终告诉我 ZIP 的位置、SHA-256、采集了多少轮、有多少轮具备首 token 分段和两端对比。不要上传网络或把原始文件内容贴进聊天。

如果目录或运行环境无法确定，完成能安全完成的部分并简短说明缺少什么，不猜测路径、不索取或读取登录凭据。
```
