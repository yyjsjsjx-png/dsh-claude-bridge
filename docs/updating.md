# 保留数据原地更新

更新插件不需要还原快照，也不需要卸载 DSH。直接升级可以保留旧会话及本机设备身份。

## 桌面与桥接两端一起升级

v0.2.24 的改动集中在远程服务。已有 v0.2.23 客户端可以继续连接，服务器也继续通过能力协商开放缓存 TTL。准备新版本源码、锁定 SDK `0.3.319` 和固定 CLI `2.1.319` 后，再在空闲窗口切换服务。升级前保留旧服务配置、源码和 CLI 以便回退。两次切换均应保持现有登录、会话和用量账本目录，按[远程服务部署](remote-service.md)核对版本、登录和监听。

v0.2.23 没有修改远程服务代码，只更新客户端插件即可；服务器继续使用 v0.2.22 也兼容。回退到旧插件时，已写入的模型路由记录会被忽略，不影响续聊。

v0.2.22 当前唯一持续维护与自动回归基线为 DSH Desktop 0.2.2-rc.1，默认使用桌面实际推送的较新版本，不再为 rc.5 等旧桌面扩展适配或保留发布门槛。桌面程序、客户端插件与远程服务分别更新；插件更新器不会替你升级桌面或服务器。建议先等待两端任务结束并备份，再更新远程服务，完全退出 DSH 后更新桌面和客户端插件，最后测试连接并核对原会话。完整压缩摘要与旧会话正文回补需要两端都更新，按服务器实际声明的 `compactionSummaries`、`compactionHistory` 能力启用，不能只看版本号。

v0.2.21 补充修复远程子代理策略隔离、Claude 原生网页首步准入及委派组失败后的状态展示。更新保留全局子代理设置和已有会话策略；此前已记录错误普通提供商策略的会话不会自动改写，需要新的选择范围时应新建远程根会话。若自定义 profile 改写了子任务设置条目的 `inject`、移除了所需门禁，远程委派组会明确禁用；普通会话的原生设置继续可用。详细边界见[远程预设与工具](compatibility-inventory.md#远程预设与工具)。

备份应覆盖 DSH 会话、桥接身份与绑定、profile 配置、Electron 实际状态及可用的旧插件源码；服务器保留旧源码和服务配置，并保护 SDK、CLI、登录配置、原生会话与账本目录。插件更新器的局部备份不能替代这些备份。若已经升级桌面，之后取得的备份只能标记为桥接切换前状态，不能当作桌面升级前快照。

旧对话摘要是尽力回补：只读既有绑定对应的原生记录，有明确边界和位置证据才原位关联；缺少位置时可追加“历史补录”，缺失、过大或对应有歧义时保留说明。展开正文仅供查看，不改变 SDK 上下文。旧卡没有正文不等于新的压缩失败，也无需强制触发一次大上下文压缩来检查升级。来源优先级和 1 MiB 上限见[压缩记录与摘要](compatibility-inventory.md#压缩记录与摘要)。

### v0.2.22 提示策略与回退

客户端通过动态上下文区分初始项目目录、当前 DSH 工具目录和服务器 SDK 环境，旧会话也能收到这些说明；不会把初始目录当作实时 cwd。SDK／CLI、远端协议和 SDK 原生会话保持不变，不需要重新登录或重建绑定。

新建绑定保存 `promptPolicy: remote-v1`，只精简已核实的原生重复身份及 Harness 自身开发／GUI 提示。已有绑定缺少该标记时继续按 `legacy` 保留原始静态提示词，即使尚未启动也不自动升级。用户指令、技能摘要和工具执行语义保留；更新不会把旧对话改成新策略。详细规则见[环境说明与提示词策略](compatibility-inventory.md#环境说明与提示词策略)。

需要回退时先等待空闲并退出 DSH，使用已备份且相互兼容的桌面、插件与远程服务组合。回退到不识别 `remote-v1` 的旧插件时，新策略绑定可能被 `SYSTEM_PROMPT_CHANGED` 等原有门禁阻止续聊；保留历史和绑定，恢复匹配插件，不要覆盖 hash、删除策略标记或复制 DSH 历史来重建 SDK 上下文。未知持久策略会明确阻止执行，不猜测降级。缺少策略标记的旧绑定继续保持原有规则。

桌面兼容范围须与提示策略分开核对：v0.2.19 当时验证的是 0.2.1-rc.5，不应在 0.2.2-rc.1 上只退该旧插件；v0.2.20／v0.2.21 的历史双版本验证不构成当前持续支持旧桌面的承诺。恢复旧展示记录也不会撤销已经发生的原生压缩。历史迁移后的安装失败另按下文[保留与失败处理](#保留与失败处理)处理。

## PowerShell 一行更新

完全退出 DSH（包括托盘程序）后，粘贴并执行：

```powershell
[Net.ServicePointManager]::SecurityProtocol = [Net.SecurityProtocolType]::Tls12; & ([scriptblock]::Create((irm 'https://raw.githubusercontent.com/yyjsjsjx-png/dsh-claude-bridge/main/scripts/update-online.ps1').TrimStart([char]0xFEFF)))
```

命令自动获取 GitHub 最新正式版本、校验安装包、调用现有更新器并清理临时下载文件。无需手动下载或解压，也无需另装 Git 或 Node.js。会话、连接和设备身份保留，程序仍使用 DSH 自带的包管理器。

支持联网安装的更新包会允许 DSH 自带的 pnpm 补齐当前缓存缺少的依赖元数据。手动解压后双击更新仍使用离线模式。安装失败时，终端会显示可识别的 pnpm 错误码和依赖名，完整输出保存在本机安装日志。

在线安装目录默认位于 `%LOCALAPPDATA%\DSHClaudeBridge\clients`；更新成功后会显示实际位置。该目录保存正在使用的插件，请保留。旧版本目录可以在确认新版本正常后清理。

命令在首次下载前为当前 PowerShell 启用 TLS 1.2，兼容旧版 Windows PowerShell 的 HTTPS 设置。若刚开始就报“基础连接已经关闭”或 SSL/TLS 错误，尚未开始安装；请核对系统时间与到 GitHub 的连接。需要代理时，先开启代理软件的系统代理，再重新打开 PowerShell；也可为首次获取脚本的 `irm` 和更新器分别传入相同的 `-Proxy`。下面以本机 HTTP/Mixed 端口 `7897` 为例，实际端口以自己的代理配置为准：

```powershell
[Net.ServicePointManager]::SecurityProtocol = [Net.SecurityProtocolType]::Tls12; & ([scriptblock]::Create((irm 'https://raw.githubusercontent.com/yyjsjsjx-png/dsh-claude-bridge/main/scripts/update-online.ps1' -Proxy 'http://127.0.0.1:7897').TrimStart([char]0xFEFF))) -Proxy 'http://127.0.0.1:7897'
```

默认升级到 GitHub 最新正式版，不限定当前安装版本；以后发布新版仍使用同一条命令。支持 `-Version 0.2.1` 指定正式版本，或用 `-DshExecutable`、`-DshHome`、`-Profile` 指定安装程序及配置。目标版本已经安装时直接提示，无需重复下载安装。

## Windows Desktop

1. 等待任务结束，完全退出 DSH，包括托盘中的程序。
2. 从[最新正式版发布页](https://github.com/yyjsjsjx-png/dsh-claude-bridge/releases/latest)下载插件 ZIP，解压到下载或文档目录，放在 DSH 配置目录以外。
3. 双击包根目录的 **`更新插件.cmd`**。更新结果窗口会保留；Windows 确实要求提升权限时才请求管理员 UAC，提权前确定的安装位置、配置和数据目录保持不变。取消 UAC 时会明确提示本次更新未执行。
4. 看到版本更新成功后，按回车关闭更新窗口，再启动 DSH。在插件页核对目标版本，再打开原会话继续使用。

脚本使用现有 DSH 自带的 Electron、pnpm 和官方插件管理接口，以离线本地包替换同名插件；不安装新的工具链，不执行包生命周期脚本，不自动启动或终止 DSH。**请保留解压目录，更新后不要移动或删除它**，包管理器可能保留对本地目录的引用。运行中的配置会被拒绝更新。

未指定程序路径时，更新器读取 Windows 安装记录、开始菜单/桌面快捷方式及已有默认安装位置，并核对文件实际存在。自定义盘符不需要改脚本；多个不同安装或未找到程序时明确拒绝，使用下面的 `-DshExecutable` 参数指定目标。安装位置、Home 和包目录在 UAC 前固定，提权后不重新猜测。

从 GitHub 安装的旧版本更新时，更新器使用带包名的 `dsh-claude-bridge@link:本地目录` 替换依赖。若旧更新器报 `ERR_PNPM_NO_OFFLINE_TARBALL` 并指向旧 GitHub 压缩包，请使用上面的一行更新命令或最新完整更新包；无需下载旧版本或关闭离线模式。安装阶段失败时，脚本会直接显示错误摘要和实际 `pnpm.log` 路径；不要把该日志与更新器外层 `.err` 混淆。安装失败不会触发自动提权或重试。

## 高级命令行

需要命令行调用时，原更新脚本继续可用：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\update-plugin.ps1
```

自定义安装位置或独立数据目录时，显式传入：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\update-plugin.ps1 `
  -DshExecutable 'D:\Apps\DeepSeek Harness\DeepSeek Harness.exe' `
  -DshHome 'D:\DSH-Test-Data' -Profile desktop
```

直接调用 `update-plugin.ps1` 若遇 Windows“请求的操作需要提升”，本次更新尚未启动，请以管理员身份打开 PowerShell 后重跑同一条命令。需要与双击入口相同的 UAC 处理和结果窗口时，可将上述脚本路径换为 `scripts\start-update.ps1`；支持相同的四个目标参数。

省略 `DshHome` 时遵循当前 `DSH_HOME`，未设置时使用用户目录的 `.dsh`。插件依赖只更新指定 profile；会话存储由同一 Home 共享，迁移会检查该 Home 的远程会话 历史，因此其他 profile 也必须退出。请在安装包目录运行脚本，不要从已安装插件的 `node_modules` 目录原地覆盖自身。

## 保留与失败处理

更新保留原 DSH 数据目录、会话历史、桥接设备身份、SDK 会话绑定及保存的连接。它不会清除连接、撤销凭据或重新登录 Claude。再次打开原远程会话时，由插件核对 SDK 原生历史；旧版展示记录的修复可能在首次空闲同步后出现。

插件安装前，脚本在目标 profile 的 `.plugin-manager/backups/claude-bridge-…` 保存 `package.json` 和已有的 `pnpm-lock.yaml`。还会检查旧版远程会话 的 V4 日志：旧同步向已闭合轮次追加消息、重复广告工具时，可能导致重启后拒绝读取。脚本仅迁移能确定属于桥接的记录，保留既有事件序号和完整消息，将展示补齐写成可忽略的插件记录。写回前执行 DSH 原生严格格式校验，临时文件落盘后原子替换。

受影响日志的原始压缩文件保存在同一备份目录的 `histories/`，属于**私人历史备份，不要上传**；未改动日志不另复制。脚本不读取认证或连接文件，不输出聊天正文。它不会删除整个会话或重新创建 SDK 绑定。该备份只包含安装元数据和本次变动的日志，不能当作完整 DSH 备份。

若更新失败，脚本会报告日志位置和元数据备份位置，不宣称更新成功。历史迁移拒绝时请先保留原日志与备份，暂勿启动 DSH，记录简短错误后再处理；不要上传完整历史。原生包管理器对兼容性拒绝会恢复安装元数据并尝试恢复依赖；其他失败可能仍需重新运行更新。若已经迁移历史但插件安装失败，应先重跑更新到新版本再启动；不要只退回旧插件。离线缓存不足时会明确失败，不会自行下载工具链。

## 从 v0.1.2 升级的提示

远程模型和思考强度现在独立记忆。以后“新建远程会话”沿用上次成功选择；型号被隐藏或不再可用时要求重新选择，不自动改用其他型号。

旧版可能已将远程模型保存成 DSH 全局默认。普通“新会话”遇到这一遗留设置时，会在创建前提示使用“新建远程会话”，避免标准预设配上远程模型。远程会话仍从专用入口创建；普通 DSH 会话使用普通模型。不会擅自替用户选一个新的普通默认模型。
